# v1.1.0 document library implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Read the approved spec and this contract before implementation; write behavioral tests first.

**Goal:** Deliver the approved multi-format local library and document editor using the existing visual theme.

**Architecture:** Preserve the Markdown compatibility boundary while adding an optional discriminated `content` value to legacy NoteDocument. Missing content means Markdown; non-Markdown values never serialize into the markdown field. Format codecs, editors and privileged file actions have separate boundaries.

**Tech Stack:** Existing React/TypeScript/CodeMirror/Tauri/Rust/SQLite plus open-source Tiptap and local PDF/export libraries.

**Spec:** docs/superpowers/specs/2026-09-08-v1.1.0-document-library-design.md

## Global constraints

- Existing themes, fonts, layout proportions, UUIDs and legacy Markdown persistence remain compatible.
- formal/temporary stays lifecycle; content.type is document/text/file. Missing content is markdown.
- No cloud, drawing, silent conversion or destructive overwrite. File writes precede index writes.
- Preserve pnpm-workspace.yaml and .cargo user changes; work in current codex integration checkout.
- No release or native platform acceptance claims without fresh evidence.

## Shared implementation contract

```ts
type RichNode = { type: string; attrs?: Record<string, unknown>; content?: RichNode[]; text?: string; marks?: {type: string; attrs?: Record<string, unknown>}[] }
type RichDocument = { schemaVersion: 1; root: RichNode }
type ManagedFile = { storageName: string; originalName: string; mediaType: string; size: number; sha256: string }
type NoteContent = { type: 'document'; document: RichDocument } | { type: 'text'; text: string } | { type: 'file'; file: ManagedFile }
type NewNoteFormat = 'markdown' | 'document' | 'text'
// NoteDocument and summaries gain content?: NoteContent. Legacy markdown stays unchanged.
// createNote input gains optional format, omitted means markdown for compatibility.
// FilePort:
// chooseFiles(): Promise<string[]> (adapter only)
// importFiles({paths, folderId}): Promise<{imported: NoteDocument[]; failed: {name:string; message:string}[]}>
// readFile(noteId): Promise<{mediaType:string; bytes:Uint8Array}>
// saveFileAs(noteId): Promise<boolean> (adapter selects destination)
// openFile(noteId): Promise<void> (safe external copy)
```

The root worker owns TypeScript contracts, dependency lockfile, service adapters, final integration, export and release verification. Backend worker owns Rust implementation. Editor worker owns new document components and editor/schema adapters. Library worker owns library UI and App integration. Shared files require coordination before editing.
