# 微屿品牌命名设计

日期：2026-08-14
状态：已确认，待用户审阅书面规格

## 1. 目标

将现有面向用户的 “Simple Notes” 品牌统一为中文名“微屿”，并保留英文名 “Cay” 供英文介绍、发布说明或其他必须使用英文的场景。品牌短句为“每个念头，都是一座小岛。”。

本轮只完成命名与轻量品牌呈现，不改变笔记功能、数据格式、同步边界或视觉布局。

## 2. 方案选择

评估过三种方案：

1. **全中文主品牌（采用）**：界面、窗口、安装器和系统菜单显示“微屿”；英文材料使用 “Cay”。品牌最集中，也最符合中文用户的使用语境。
2. **中英文并列**：统一显示“微屿 Cay”。信息完整，但在窗口标题、导航栏和便签窗口中显得冗长。
3. **界面中文、安装器英文**：界面显示“微屿”，安装器显示 “Cay”。技术上可行，但容易让用户误认为安装包和应用不是同一个产品。

## 3. 用户可见命名

- 主窗口、设置页、便签窗口、浏览器标题、安装器产品名和系统菜单统一显示“微屿”。
- 无内容欢迎区或品牌介绍位置可显示“每个念头，都是一座小岛。”；高频编辑界面不重复展示宣传语。
- 英文 README、英文发布说明或受限于英文字符的渠道使用 “Cay”。需要同时消除歧义时可首次写作 “Cay (微屿)”。
- 更新、重启和存储迁移等用户提示中的旧品牌名同步替换为“微屿”。
- 导出目录面向用户，改为“微屿导出”；其内部清单格式保持兼容。

## 4. 保持稳定的内部标识

以下技术标识本轮不改：

- Tauri 应用标识 `app.simplenotes.desktop`；
- Rust crate、JavaScript package 和内部命令名称中的 `simple-notes`；
- 已落盘的迁移标记、临时文件前缀和 E2E 存储键；
- 已发布协议、权限名称和数据库格式。

这些值不是常规用户界面的一部分。保留它们可以确保现有应用数据目录、笔记、设置、更新协议和恢复文件继续被识别，避免改名后出现“数据消失”或无法恢复的假象。

## 5. 界面呈现

- 现有暖色、圆角、自然风格不重做，仅替换文字品牌并校准长度。
- 主导航品牌标题使用“微屿”，不附加 “Cay”。
- 宣传语只在没有选中笔记的欢迎状态或品牌介绍区域出现一次。
- ARIA 应用名称同步为“微屿”，保证屏幕阅读器与可见品牌一致。
- 不新增网络字体、第三方商标资产或受限素材。

## 6. 兼容与发布

- 本轮无数据迁移。
- 安装器显示名改变，但应用标识保持不变，因此应继续使用原应用数据。
- 发布资产名称若由 Tauri 产品名生成，可包含“微屿”；英文发布页面将产品称为 “Cay”。发布校验必须继续接受实际生成的各平台资产，不能仅以旧品牌字符串硬编码判断。
- `master` 保持初版基线；品牌工作在 `codex/weiyu-branding` 隔离分支完成，预览确认后再合并。

## 7. 测试与验收

- 添加品牌合同测试，验证主界面、设置、便签、HTML 标题与 Tauri 产品名均使用“微屿”。
- 验证旧的 `app.simplenotes.desktop`、内部文件前缀和包名保持不变。
- 更新受品牌名称影响的 UI、导出和发布元数据测试，不放宽安全或资产身份校验。
- 运行 TypeScript 测试、类型检查、ESLint、Rust 相关测试和生产构建。
- Windows 实机预览确认窗口标题、开始菜单/安装器显示名和现有本地数据可见；macOS 显示名留待原生平台 RC 验证。

## 8. 缓存维护说明

Rust 的 `target` 是可再生构建缓存，不属于发布包。一次干净构建通常不会立刻恢复到此前约 40 GiB；长期反复执行 debug、集成测试和 release 构建后仍可能增长到数十 GiB。项目文档将说明可用 `cargo clean --manifest-path src-tauri/Cargo.toml` 安全清理，并提醒清理后的首次编译会更慢。
