## 原始缺陷证据

本轮只审查和复现，没有修改业务实现。四项 P1 涉及遗漏保存、错误覆盖或意外改变内容；五项 P2 涉及交互、格式转换和性能。这里的优先级是本项目的工程判断，不代表外部厂商认证。

## P1：上线阻断

### T01：Markdown 当前单元格内容未进入保存草稿

位置：`src/features/editor/documentWidgets.ts:402`、`:456`；`src/features/editor/MarkdownSource.tsx:297`。

复现：在一个单元格里输入 `unsaved draft`，保持焦点；调用 `beginEditBarrier()`。输入事件只更新 textarea 的 title/尺寸，`onChange` 调用次数仍为零。真实 Chromium 中，输入后等待 1.5 秒，父编辑器草稿仍是旧内容。

影响：自动保存不知道这些输入，保存状态可能与可见内容不一致。保存屏障只等待图片而不提交表格编辑；不触发单元格 change 的退出、重启、导出或视图重建路径存在遗漏最新内容的风险。本轮没有声称所有鼠标离焦路径都会丢失。

修复要求：建立表格编辑草稿契约，在自动保存及屏障前统一提交当前单元格和组合输入；屏障完成后禁止继续写入。覆盖聚焦输入后的保存、退出、切换视图、导出、失败恢复与重新打开。

### T02：富文档矩形选区的 TSV 从末端格开始粘贴

位置：`src/features/document/tablePaste.ts:13`、`:41`、`:56`。

复现：在 3×3 表格中设置左上 2×2 的 CellSelection，粘贴 `x\ty\nz\tw`。实际写入第 2–3 行、第 2–3 列，原选区前三格没有被替换；原选区之外的格子被覆盖。在 2×2 整表选区中，相同粘贴函数直接返回 false。

原因：使用选区 `$from` 所在的格子作为粘贴起点，没有按 CellSelection 的逻辑矩形取左上角。已通过真实浏览器剪贴板事件确认，不只是对辅助函数的推测。没有发现并声称本次复现产生嵌套表格。

修复要求：区分普通文本选区、CellSelection 和整表选区，统一使用表格逻辑坐标定位；正向/反向选区都从目标矩形左上角开始，不能覆盖意外区域。

### T03：富文档 rowspan 导致跨行粘贴错列

位置：`src/features/document/tablePaste.ts:30`。

复现布局：第 1 行 `[A0（跨两行）, B0, C0]`；第 2 行 `[被占用, B1, C1]`；第 3 行 `[A2, B2, C2]`。从 B1 粘贴 2×2 矩阵。第 3 行期望 `[A2,z,w]`，实际 `[z,w,C2]`，A2 被覆盖。

原因：每个物理行都把 column 重置为 0，只累加 colspan，没有计算上方 rowspan 占用的位置。

修复要求：使用逻辑 TableMap/等价占用网格；按真实行列计算起点、目标与合并覆盖边界，所有写入在一次可撤销事务内完成。

### T04：编辑另一格会改变原有 Markdown 转义语义

位置：`src/features/editor/markdownActions.ts:322`，通过 `tableMarkdownFromModel()` 全表重写触发。

复现：第一格原文 `\*literal\*`，第二格 `old`。只把第二格改成 `new`。第一格原来渲染为字面量 `*literal*`，重写后渲染为带反斜杠的斜体内容 `\<em>literal\</em>`。

原因：表格解析没有把所有 Markdown 转义按同一语义解码，序列化却无条件加倍反斜杠。内部模型往返相等不足以证明真实 Markdown 渲染语义相等。

修复要求：未修改格子的源码/语义必须保留；补充转义、代码、链接、内联公式、管道和反斜杠的真实渲染往返测试。

## P2：交互与体验

### T05：富文档鼠标选区与原生文本选择冲突

位置：`src/features/document/RichDocumentEditor.tsx:526`、`:722`。

已在工具栏展开的稳定布局中复验，并避开左上角全选按钮。跨格拖选后，期望四个 selectedCell，实际为零，编辑器最终 selection 为普通 text 类型；同一格内拖动约 60px，结果选中了整格的 19 个字符，无法保持子串选择。

实现对同一格中的 mousemove 也执行 `setCellSelection`，并与 ProseMirror/浏览器原生拖选同时工作。具体事件竞争的最终修复需要补充生命周期验证，不能只靠添加更多 focus 调用。

修复要求：明确同格文字选择与跨格矩形选择的切换阈值，保证 mouseup 后选区稳定；覆盖多次移动、跨边界、滚动、缩放和随后复制/删除/格式化。

### T06：Markdown 不支持 Excel 的带引号多行 TSV

位置：`src/features/editor/documentWidgets.ts:423`；富文档已有独立的 `parseTsv`。

复现：粘贴 `"alpha\nbeta"\tX`。这是一个含换行的字段加第二列，实际拆成两行，原本应有两行（表头+正文）的表格变成三行，内容和列对齐发生变化。

修复要求：共享经过验证的 TSV 解析契约；保留引号、双引号、空尾列和 CRLF。Markdown 无法原生表达的格内换行应采用明确的可逆表示或说明限制，不能把字段换行当作新表格行。

### T07：Markdown 多选与批量操作不一致

位置：`src/features/editor/documentWidgets.ts:322`、`:326`、`:457`。

已复现：选中两行后点击“删除行”，只删除选区最上方的一行。列删除使用同样的单索引方式。代码也没有对矩形选区实现 TSV 复制或批量清空，键盘仍进入 textarea 的文本操作。

前者是当前选区与动作不一致的复现；复制/批量清空属于能力缺口，不声称已复现系统剪贴板数据丢失，也没有读取或写入用户的系统剪贴板。

修复要求：明确“当前行/列”还是“所选行/列”的产品契约；若保留矩形选区，应提供匹配的复制、清空和批量增删反馈，含一次撤销及边界保护。

### T08：Markdown 转文档把表格压成普通段落

位置：`src/features/document/markdownConversion.ts:191`。

复现：标准 GFM 表格转换后没有 table 节点，也没有逐字保留原文的 rawMarkdown；多行通过 `paragraph.join(' ')` 压成一段。原笔记作为副本来源仍被保留，因此没有把它归为原文件丢失。

修复要求：识别标准表格并保留对齐/合并信息；暂不支持的构造至少逐字保留，界面说明转换限制，不能将转换副本称为表格保真转换。

### T09：中型 Markdown 矩阵粘贴会阻塞主线程

位置：`src/features/editor/documentWidgets.ts:438`；`tableWithCell()` 每次克隆表格。

在本机 Chromium 中，把 200×20 的 TSV 粘贴到小表，事件同步耗时约 **651.6ms**，最后一格值正确。该数据是一次本地测量，不是跨设备 p95，也没有把它描述成所有机器都相同的结果。

原因：每个目标格都克隆整个表格，再重建全部 textarea/监听器；成本随目标格数量显著放大。用户会在普通电子表格粘贴规模下感觉停顿。

修复要求：一次性构造目标网格并原子提交；为大粘贴设可取消且不丢草稿的处理边界，建立 20×10、200×20、1000×20 的耗时/响应性基线。不能用最终值正确代替流畅度验收。

## 上线验收建议
