# 微屿托盘与应用生命周期设计

日期：2026-09-04
状态：用户于 2026-09-04 批准详细设计；2026-09-07 已形成源码候选，原生平台验收尚未完成。

## 1. 目标与范围

主窗口关闭后可继续在后台运行，通过系统托盘恢复同一个窗口，保留当前笔记、选区、滚动位置与窗口尺寸。临时便笺和全局捕获快捷键继续工作。

这不是崩溃恢复功能：进程崩溃、强制结束及断电无法靠托盘维持运行。现有原子保存与启动恢复仍是数据保护基础。不增加驻留守护进程、云服务、后台更新或轮询任务。

## 2. 方案选择

采用 Tauri 原生托盘/菜单加应用级生命周期协调器。原生菜单负责平台交互、键盘导航与系统主题，协调器区分隐藏、退出及重启意图，复用现有保存屏障。

未采用的方案：

- 仅在关闭事件中调用 hide：改动小，但无法安全处理多窗口退出、保存失败、恢复入口不可用和重启。
- 独立常驻后台进程：隔离更强，但增加进程通信、升级和故障恢复复杂度，超出本次需求。

## 3. 用户交互

### Windows

- 主窗口 × 和 Alt+F4 均遵循关闭行为设置；最小化仍进入任务栏，不偷换为托盘隐藏。
- 设置项为“关闭主窗口时隐藏到托盘”，默认开启。首次关闭先显示应用内说明，让用户明确选择“隐藏到托盘”或“退出软件”，支持记住选择；不依赖系统通知权限，不反复打扰。
- 关闭到托盘只隐藏主窗口，不销毁编辑器，不隐藏现有便笺。隐藏成功后释放临时编辑屏障，再次打开可以正常编辑。
- 单击托盘图标恢复并激活主窗口；连续点击不得创建新窗口或重复触发动作。右键打开系统原生菜单。
- 恢复时取消最小化，沿用窗口尺寸；显示器移除后将窗口限制在当前可用工作区。已显示的窗口只激活，不闪烁式隐藏/显示。
- 托盘可能在 Windows 溢出区，由用户决定其位置，不修改系统任务栏偏好。

### macOS

- 使用原生菜单栏图标；点击图标显示菜单，通过“打开微屿”恢复主窗口，不强套 Windows 的左键/右键分工。
- 保留 Dock 与标准应用菜单入口；Dock 激活可以恢复主窗口。
- 关闭窗口与退出应用分开：红色关闭按钮及 Cmd+W 关闭/隐藏窗口，Cmd+Q 和“退出微屿”请求真正退出。
- Windows 的“关闭即退出”设置不强加到 macOS；设置文案按平台适配，菜单栏图标可关闭，但 Dock 恢复与标准退出入口必须保留。

### 原生菜单

固定顺序：打开微屿、新建临时便笺、打开临时便笺收件箱、分隔线、设置、分隔线、退出微屿。

收件箱与设置先恢复主窗口，再通过有类型的应用动作请求导航；不得绕过当前笔记保存检查。新建便笺复用现有捕获服务，不要求先显示主窗口。启动尚未就绪、数据恢复阻塞或正在退出时，相关动作禁用并提供状态反馈。菜单不显示笔记正文或私人标题，不添加导出、删除等复杂或破坏性操作。

## 4. 状态与保存协议

协调器显式管理 Visible、PreparingHide、Hidden、PreparingExit、Exiting，以及独立的重启意图。窗口可见性与进程退出授权不是同一个布尔值。

隐藏流程：请求隐藏 → 检查托盘入口可用 → 主窗口进入编辑屏障并等待待完成的图片粘贴/保存 → 保存成功后隐藏 → 释放屏障。保存失败或隐藏失败时保持窗口可见、释放屏障并提示重试。启动尚未完成时不直接隐藏，显示可恢复状态。

退出流程：

1. 同步进入 PreparingExit，暂停新建便笺及会制造新编辑状态的动作。
2. 为本次退出生成代次标识，冻结需要确认的存活编辑窗口集合，包括隐藏的便笺。
3. 各窗口进入编辑屏障，等待已经开始的图片保存与内容写入，并返回持久化成功确认。
4. Rust 验证发起窗口身份、注册令牌、退出代次及窗口集合；拒绝过期、重复和伪造的确认。
5. 只有全部成功后才授权退出，并清理托盘、快捷键和窗口资源。
6. 任一失败、窗口无响应或确认超时，都取消普通用户退出，释放已获得的屏障、恢复动作，显示主窗口及必要的出错便笺；不静默丢弃内容。确认等待上限为 10 秒，超时只是取消退出，不中止底层原子写入；后续旧确认不得触发退出。

隐藏操作成功不能留下 approved-exit 标记。重复关闭合并处理；退出优先于尚未完成的隐藏。准备隐藏期间收到打开请求则取消最终隐藏，保持前台。取消退出后必须可继续编辑、再次保存和再次退出。

应用内更新重启走显式安全重启意图，不被“关闭到托盘”拦截，也不绕过多窗口保存确认。移动数据位置必须先对所有实时编辑器执行一次独立的迁移前保存，包括隐藏便笺；任一保存失败或超时均取消迁移。保存全部确认后才获取现有迁移锁、复制并发布目标目录，成功后将这一轮拥有的编辑屏障交接给随后的安全重启，失败则释放屏障并恢复编辑。保持现有显式更新策略，不添加静默安装。

## 5. 系统与异常边界

- 单实例：再次启动程序只激活已有实例，不能出现多个托盘图标或两个进程写同一笔记库。在打开存储前建立实例协调；忽略未定义的外部参数，不因此引入深链接能力。
- 托盘创建失败：保持主窗口可访问，禁用本次会话的托盘隐藏并明确提示；不暗中修改用户持久化偏好。用户仍可安全退出。
- Windows Explorer 重启：验证托盘重新注册；恢复失败时恢复主窗口。若现有库无法报告此故障，不宣称已覆盖，必须在平台验收中解决后再发布。
- 系统注销/关机与普通关闭区分处理，绝不能因驻留策略把关机请求变成隐藏。使用平台允许的有限保存机会；系统强制终止不保证最后一段未持久化输入，依靠日常自动保存与恢复降低损失，不无限阻塞关机。
- 开机启动维持用户现有选择；启用托盘不自动启用开机启动。手动退出不偷偷重启进程。
- 无请求时不抢焦点、不闪烁图标、不反复通知。后台不新增定时轮询或动画；保存失败要有可发现的恢复入口。

## 6. 架构与兼容性

Rust 托盘适配器持有单个原生图标并分派枚举动作；平台差异封装在窗口适配层。应用生命周期协调器负责意图、代次、窗口集合和超时。React 只通过有类型的生命周期/导航服务执行保存及视图切换，不直接获得任意退出或文件权限。

扩展现有主窗口 CloseCoordinator 与 renderer 注册协议，而不是另外创建一套不相干的退出通道。便笺加入应用级退出确认，保留其正常关闭即隐藏的既有规则。实现前检查库编辑器与便笺对同一笔记的并发写入约束，不能以“最后一个确认覆盖前一个”掩盖冲突。

设置增加带默认值的可选持久化字段，旧配置仍可读取；首次说明是否完成与用户关闭偏好分开记录。沿用原有包标识、存储根和笔记格式，不迁移 Markdown 或 SQLite 笔记内容。对现有产品规范与 AGENTS.md 的窗口规则在本设计批准后同步更新。

## 7. 验收标准

- 状态机测试：重复请求、隐藏/退出竞争、过期确认、无响应、失败取消、取消后重试、恢复期间取消隐藏、重启不被隐藏。
- 前端测试：首次说明与设置持久化、隐藏后恢复编辑、未完成图片粘贴、保存失败不隐藏、菜单导航遵守保存屏障。
- 多窗口集成：主窗口及可见/隐藏便笺都有待保存内容；任何一个失败不得退出；全部成功后落盘内容完整。
- Windows 实机：×、Alt+F4、最小化、托盘点击、键盘菜单、二次启动、Explorer 重启、DPI 100/150/200%、明暗/高对比主题、多显示器变化、注销与关机。
- macOS 实机：菜单栏、Dock 恢复、Cmd+W/Cmd+Q、明暗外观、登录启动及退出。未执行的平台验证必须明确记录为未验证，不宣称跨平台完成。
- 无障碍：原生菜单有文本名称、合理顺序、禁用状态、键盘/Escape 操作；托盘图标识别清晰，不仅依赖颜色；应用内首次说明与错误提示具备焦点管理。
- 资源：比较可见、隐藏且空闲两种状态的 CPU/内存，不新增持续轮询、泄漏或重复监听；关闭与恢复反复执行后仍只有一个托盘和一组监听器。

按改动范围先跑聚焦 Rust/前端测试，再做类型检查、相关 Rust check/Clippy 和平台烟测。由于涉及退出时的数据安全，合入发布候选前补做存储/恢复相关回归；不以纯 mock 菜单测试代替真实系统托盘验收。
