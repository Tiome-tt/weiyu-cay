# 微屿 v1.1.0：文档与多格式资料库

日期：2026-09-08

状态：用户已批准功能方向及开发，本文将讨论落实为可审查的技术规格；等待书面规格审阅。

## 1. 已确认的目标

- 本次目标版本为 v1.1.0，当前 package.json 版本为 1.0.2。
- 两个交付重点：结构化文档编辑，以及常用格式文件的保存、组织和适当预览。
- 保留当前微屿的主题、字体设置、颜色变量、窗口外观、分栏与密度；概念图仅作为功能示意，不作为视觉替换稿。
- 绘图不在本版范围。
- 本地优先、完全离线、无需账号、稳定 UUID、可恢复删除和文件为持久真相继续成立。

本规格在书面批准后补充并取代原始设计中“所有正式内容均为 Markdown”和“全部正式笔记采用三种视图”的限制。其余原始设计，特别是托盘、退出保存、数据目录迁移、签名发布和更新约束继续有效。实施首步同步更新 AGENTS.md 与原设计，避免留下互相冲突的规则。

## 2. 范围和能力

| 内容类型 | 新建/导入 | 编辑和查看 | 输出 |
| --- | --- | --- | --- |
| 文档 | 默认新建；显式从 Markdown 转换副本 | 结构化所见即所得编辑 | 原生文档、PDF、DOCX |
| Markdown | 新建、导入 .md | 现有源码、分栏、阅读视图 | 原始 Markdown、PDF |
| 纯文本 | 新建、导入 .txt | 纯文本编辑，不解释 Markdown | UTF-8 .txt |
| PDF | 导入 .pdf | 离线页面阅读、缩放、翻页 | 原文件另存 |
| 图片 | 导入 .png/.jpg/.jpeg/.webp | 离线图片预览；可插入正文 | 原文件另存 |
| Office | 导入 .doc/.docx/.xls/.xlsx/.ppt/.pptx | 文件信息、用系统应用打开 | 原文件另存 |
| 其他附件 | 导入其他普通文件，例如 .zip | 文件信息 | 原文件另存 |

Office 原文件编辑、Office 正文搜索、OCR、绘图、PDF 批注、附件外部编辑自动同步、云服务和协作不在本版范围。导出 DOCX 不表示支持导入 DOCX 后原生编辑。其他附件不提供任意可执行文件的一键运行入口。

Markdown 转换创建新的文档副本、新 UUID，并保留原笔记和原有链接。内部引用在支持的转换范围内保留目标 UUID；未知 Markdown 构造保留为可查看、可复制的原文块。转换不能悄悄删除内容。双向有损转换不是视图切换，本版不提供普通文档切换到 Markdown 源码的按钮。

## 3. 当前实现依据

- TypeScript `src/domain/model.ts` 与 Rust `src-tauri/src/domain.rs` 的 NoteDocument 只有 markdown 正文，NoteKind 表示 formal/temporary 生命周期。
- `src/features/editor/useAutosave.ts` 按 Markdown 字符串管理草稿、版本和持久保存。
- `src/features/editor/EditorPane.tsx` 管理三个视图、保存屏障、标签及内链操作。
- `src-tauri/src/storage/repository.rs` 的加载、写入和恢复描述符直接使用 note.md。
- recovery、rebuild、export 和 temporary_ops 依赖原有持久格式，不能只修改编辑器而忽略它们。
- 现有文件夹是逻辑组织，物理内容使用 UUID 目录，适合继续作为统一资料库基础。
- 数据库已存在四次迁移；新增迁移必须兼容现有数据库及无数据库重建。

## 4. 内容模型与边界

保留 formal/temporary 的生命周期含义，另外引入内容类型 markdown/document/text/file，禁止将附件类型混入临时/正式状态枚举。

统一条目元数据包括 UUIDv7、生命周期、内容类型、标题、逻辑文件夹、标签、revision、创建和更新时间。正文使用 TypeScript 可辨识联合与等价的 Rust serde 类型：Markdown 字符串、结构化文档、纯文本、受管文件描述。禁止把结构化 JSON 塞入 markdown 字段或用改后缀伪装 Word 格式。

编辑器、内容解析器和存储编解码器分开：

- Markdown 继续使用 CodeMirror 和既有解析链。
- 文档使用成熟的结构化富文本引擎，首选评估 Tiptap/ProseMirror 开源核心；版本和许可证在锁定依赖时核验。不引入付费云服务或第二套状态/样式框架。
- 文档持久 schema 由微屿版本化定义，编辑器适配层负责映射，避免把不受控的插件 JSON 当永久契约。
- 纯文本使用 CodeMirror 的纯文本配置。
- PDF、图片和附件使用专用阅读组件。
- React 通过 typed service/port 操作，文件、SQLite、路径和系统打开仍由 Rust 命令验证。

新自动保存核心接收不可变的类型化正文快照和版本，而不是依赖 Markdown 字符串。保留现有在途保存串行化、切换笔记防串写、脏状态、冲突反馈和编辑屏障语义。隐藏便笺仍参与退出与重启保存。

## 5. 持久文件与原子发布

旧内容保持 `notes/<uuid>/note.md`；已有便笺保持 `temporary/<uuid>/note.md`，不做静默批量转换。

新文档使用 `notes/<uuid>/note.cay.json`，单文件含格式标识、schemaVersion=1、完整元数据及结构化正文。图片等资源位于同目录 assets。导出时使用可读标题和 `.cay.json` 后缀。

新纯文本与导入文件使用单个原子发布的 `entry.json` 清单，包含完整元数据、内容类型以及指向同目录不可变 payload 的相对引用。纯文本每次保存先写入新 payload，再原子发布清单，旧 payload 在确认不被有效/恢复清单引用后才允许清理。纯文本 payload 为 UTF-8，导出为普通 .txt；不会把应用元数据写进用户正文。

导入文件保留原始字节，payload 使用随机安全文件名，清单保存原文件名、扩展名、检测类型、大小及完整性摘要。资源引用只允许受管相对路径。索引必须能仅靠 note.md、note.cay.json、entry.json、payload 和 folders.json 恢复。

每个 UUID 目录只能有一个生效入口。发现多个入口、未知 schemaVersion、缺少 payload、摘要不匹配或非法文档结构时保护原内容并报告错误，不自行选择“最新”的入口覆盖另一个。

全部保存沿用同目录临时写入、flush、原子替换及平台恢复协议；文件发布成功后才能事务性更新索引。恢复标记按入口文件名扩展，保留旧 note.md 标记兼容。不得以更新 SQLite 的方式伪造成功保存。

## 6. 导入、安全和外部打开

导入默认复制，不移动用户源文件。文件选择和拖入采用同一服务，批量逐项给出成功与失败，重试不覆盖已成功项。Rust 接收经文件选择/拖放边界授权的来源，拒绝目录、符号链接/重解析逃逸和非法目标路径，按流复制，不把大文件整个编码为前端数组。

导入流程：验证来源与大小 → 复制到暂存 payload 并计算摘要 → flush → 原子发布条目清单 → 建索引。中断发生在清单发布前，不出现可见半成品；发布后索引失败，可通过重建恢复。

首版单文件导入上限 256 MiB；可编辑文本上限 16 MiB；超限保留用户原文件并给出明确说明。文本导入识别 UTF-8（含 BOM）和 UTF-16 BOM；无法可靠解码的文件允许按附件保存，禁止用替换字符写坏原文。扩展名用于展示，实际预览还需类型检测及解析验证。

PDF/图片预览不执行嵌入脚本，不自动访问远程资源；PDF 阅读实现需本地打包依赖，在 Windows/macOS WebView 均验证，不依赖浏览器自带 PDF 插件。附件路径不传给组件作任意文件访问授权。

“用系统应用打开”针对列明的 Office 类型提供。打开的是受管原件的独立缓存副本，明确说明外部修改不会自动同步，可重新导入；避免绕过版本/摘要管理修改持久原件。另存使用显式选择目标，重名不静默覆盖。

## 7. 文档编辑和表格

文档支持段落、六级标题、粗体、斜体、删除线、下划线、高亮、引用、有序/无序/待办列表、代码块、分隔线、图片、外链、UUID 内链和附件引用。

`# ` 输入规则生成标题，`==文字==` 生成高亮；代码和字面原文中不触发。快捷转换可一次撤销。Markdown 的既有行为保持兼容；新增 Markdown 高亮解析时，编辑、预览、索引提取和导出需共享语义测试。

表格为正文块，默认占可用编辑宽度；大表格只在表格区域水平滚动，页面不同时出现重复的无意义滚动条。单元格多段落自动增高，不裁切文字。

首版表格支持：

- 点击定位、中文输入法、Tab/Shift+Tab 单元格导航、末尾 Tab 添加行。
- 行列插入和删除、矩形选区、批量清空、复制剪切粘贴。
- HTML 表格及 TSV 粘贴；合并格和不规则表格通过统一规范化处理，不按屏幕文本随意拆列。
- 调整列宽并持久化；行列边缘控件具有可访问名称和键盘替代入口。
- 矩形兼容选区合并、拆分恢复、对齐和有限主题友好底色。
- 单元格内段落、列表和基础行内格式；不允许嵌套表格。
- 选中表格时出现就近工具栏和右键动作；离开后收起，焦点不能被工具栏吞掉。
- 单次结构操作与粘贴各自作为完整撤销事务；工具操作先提交/保护输入法组合状态。

保存 schema 明确保存行列跨度、列宽和单元格属性；Rust 验证表格无重叠/越界跨度、节点层级、允许属性和合理结构上限。非法或未知结构不能被静默修复后覆盖有效文件。

## 8. 资料树和阅读布局

沿用当前三栏与 CSS tokens，保持各主题、用户字体、最小列宽、双击恢复比例和键盘导航。不会替换应用图标或导入概念图中的 Office 品牌图标；用既有 Icon 系统表达文件类别。

- 文件夹内混排条目，完整树自然滚动，不新增每文件夹独立滚动容器。
- 新建入口提供文档（默认）、Markdown、纯文本、文件夹、导入文件。
- 通过紧凑类型图标和原文件扩展名区分条目；文档无需展示技术后缀。
- 支持批量选择、移动、重命名、回收站、拖入文件、按名称/修改时间排序及类型筛选。
- 筛选时保留命中的祖先文件夹，不修改持久排序；只有手动排序视图允许拖动重排。
- 点击文档显示标题目录，Markdown 保留现有目录；PDF 有书签时可显示书签。纯文本、图片、普通附件收起目录，不覆盖用户原有文档列宽偏好。
- 工具栏按条目能力显示操作：文档不显示源码按钮，附件不显示富文本格式按钮。
- 附件既可以在资料树中独立管理，也可以通过 UUID 卡片引用到文档；删除目标显示可恢复的失效卡片，不级联删除其他文档。

## 9. 搜索、内链与恢复

文档/Markdown/纯文本支持标题、正文、标签搜索。附件首版按文件名与标签搜索，不承诺 PDF/Office 正文检索。

内容适配器提供纯文本提取、标题大纲、UUID 链接提取和可见标签修复；TypeScript 与 Rust 用共享 fixture 保持一致。文档原生内链存 UUID 与显示标签，Markdown 保留既有转义语法。改名后目标 UUID 不变，引用标签修复失败沿用现有可重试机制。

回收站操作移动完整条目及资源，清单保留类型、原文件夹和修订；恢复不能猜成 Markdown。资料库搬迁、整库导出、启动恢复和重建必须涵盖所有类型。清理不能删除仍被历史恢复候选引用的 payload。

升级前提示备份并提供原有完整导出；启动新版本不得批量重写旧正文。新格式库不能承诺旧应用版本完整支持：资料库版本标记和升级说明必须明确降级边界，必要时从升级前备份恢复，不允许用旧版操作新格式条目。

## 10. 导出

单条文档：原生文档、PDF、DOCX。Markdown：.md 与 PDF。纯文本和附件：原文件/正文另存。整库导出重建逻辑文件夹，包含所有原生条目、元数据清单和资源，重名生成安全名称并报告映射。

PDF/DOCX 使用与文档 schema 同源的转换层，保留中文、基础格式、图片、表格、行列跨度、列宽和外链。平台字体替换、分页和超宽表格需要导出预览验收；转换失败不得生成带成功提示的残缺文件。无法表达的原生内部引用以可读标签输出，原生备份继续保留 UUID。

## 11. 实施边界和依赖顺序

1. 内容模型及编解码：新增格式模块与共享 fixture；扩展 Rust 存储路由和迁移；验证旧内容不变、新内容可重建。
2. 可靠保存与恢复：泛化 autosave，接通退出屏障、回收站、重建、搬迁及整库导出。
3. 文档编辑：隔离富文本组件及编辑器/schema 适配，接入表格、图片、内链、目录、附件引用。
4. 文件管理：Rust 导入/读取/另存/外部副本打开端口，接入纯文本、PDF、图片与附件面板。
5. 资料树：新建类型、混合条目、筛选排序、拖入与批量操作，复用现有主题和组件。
6. 导出与发布验收：PDF/DOCX 转换、全链路数据安全验收、版本同步至 1.1.0。版本号变更不等于发布成功，不自动发布正式版本。

不把“编辑器能输入但保存/恢复缺失”作为完成的阶段交付。

## 12. 验收与测试

每个行为变更先写失败测试，再实现并跑相关测试。具体用例包括：

- 旧 note.md 字节内容与 UUID 不受升级影响，三视图与便笺行为保持。
- 新文档保存重开后结构、中文、合并格、列宽、高亮和附件引用完全一致。
- 中文输入中点击工具栏、连续撤销重做、粘贴 Excel 多行、切换笔记及并发保存不串写不丢字。
- 失败注入覆盖 payload 写入、清单发布、内容替换、索引事务各阶段，旧修订始终可恢复。
- 断电残留、多入口冲突、未知格式、非法跨度、重复 UUID、损坏 payload 都不静默覆盖。
- 删除数据库后，所有类型、文件夹、标签、链接和附件能重建；恢复回收站及搬迁能保留全部字节。
- 路径遍历、符号链接、伪扩展名、非法图片/PDF、超限文件和批量部分失败。
- 类型切换、筛选祖先、排序、多选、重命名、删除撤销、目录收起恢复、主题与键盘焦点。
- PDF/DOCX 实际生成后检查中文、长表格、图片、合并单元格与资源完整性，不仅验证文件存在。

本版涉及跨类型存储、恢复和索引，最终需完整 Rust suite、cargo check/Clippy、相关及跨组件前端测试、typecheck、lint、UI build 与 10,000-note 搜索 fixture。开发中按变更先执行最小关联测试，不在每一步重复全量检查。

发布前分别执行 Windows/macOS 桌面原生验收，包括 PDF、文件选择/拖入、系统打开、退出/重启屏障、隐藏便笺、安装升级、签名及更新。未执行的平台验收必须明确列为未完成，不以 web UI 测试替代。
