# 微屿主窗口视觉重设计

Date: 2026-08-14
Status: Approved

## 1. 目标与范围

本轮只重设计微屿主窗口。目标是把当前偏开发中后台页面的界面，改成现代、紧凑、安静且适合长期写作的桌面产品。

本轮包括：

- Windows 与 macOS 主窗口外壳。
- 全局应用栏、搜索、新建笔记和设置入口。
- 资料库栏、笔记目录栏及两栏的独立折叠状态。
- 正文工具栏、空状态和主窗口反馈组件的统一视觉。
- 浅色、深色和跟随系统主题。
- 新的“圆丘岛”应用图标。

本轮不包括：

- 快捷便笺窗口的完整视觉重设计。
- 设置页和临时收集箱的结构性重设计。
- 笔记存储、SQLite、Markdown 格式、搜索算法和同步功能变化。
- 新的组件框架、样式框架或状态管理框架。

快捷便笺后续沿用本轮品牌语言，并探索顶部小星、底部正视小岛的主题构图。该设想不在本轮实现。

## 2. 视觉方向

主窗口采用“潮汐纸页”方向，并使用专业紧凑的信息密度。视觉目标不是做卡通海岛界面，而是在专业 Markdown 工具中加入属于微屿的海岸记忆。

主窗口的正文是视觉主角。品牌通过以下少量元素体现：

- 海湾绿的主操作与选中潮线。
- 暖星色的小面积状态点。
- 空状态中的圆丘岛轮廓。
- 低饱和海岸色阶，而不是大面积插画。

圆丘岛装饰只出现在 App 图标、空状态和少量欢迎区域。打开笔记后，正文区域不显示品牌装饰。

## 3. 颜色、字体和形状

### 3.1 核心色板

- 岸纸白 `#F8FAF7`：浅色正文和应用栏。
- 雾叶绿 `#EAF0EB`：浅色资料库背景。
- 海湾绿 `#2F7866`：主操作和品牌色。
- 潮线绿 `#58A38E`：选中标识、拖拽边界和辅助强调。
- 暖星色 `#D59A5E`：极少量品牌点缀。
- 海墨色 `#172621`：深色正文基底。

深色主题使用墨绿色夜海色阶，不使用纯黑背景。所有文本、代码块、焦点环和错误状态必须达到清晰可读的对比度。

### 3.2 字体

界面使用操作系统自带的现代中文无衬线字体：Windows 优先 `Segoe UI Variable` 和系统中文字体，macOS 优先系统 UI 字体。不得为主窗口额外下载 Web 字体。

- 品牌名和分区标题使用较紧凑的显示字重。
- 普通控件使用常规 UI 字重。
- Markdown 正文、代码字体、字号和行高继续遵循用户设置。
- 代码继续使用系统等宽字体栈。

### 3.3 形状和层级

- 常规圆角范围为 7–12px。
- 三栏使用细分隔线和轻微色阶建立层级，不把每栏都设计成独立大卡片。
- 阴影只用于浮层、菜单、搜索结果和当前选中笔记。
- 当前项目左侧显示一条细潮线；不得只依靠背景色表达选中状态。
- 动画时长控制在 120–160ms。启用减少动态效果时取消非必要动画。

## 4. 应用图标

新图标采用正视角“圆丘岛”，不使用俯瞰轮廓或单独波浪符号。

图标由四层组成：

1. 蓝绿色海面背景。
2. 平缓的绿色岛丘。
3. 更宽的暖色沙岸。
4. 下方两层简化海浪和顶部一颗暖色小星。

岛丘顶部略微压平，避免看起来像普通山峰。沙岸与海浪必须在 16px 时仍可区分。图标应输出 Windows 与 macOS 所需的完整图标尺寸，并用于应用栏、窗口、任务栏、安装器和系统应用列表。

图标必须原创，不使用 Nintendo、动物森友会或其他第三方受保护素材。

## 5. 窗口外壳与全局应用栏

主窗口顶部使用两层结构。

### 5.1 自绘标题栏

第一排只承担窗口拖动和系统窗口控制：

- 不显示 App 图标。
- 不显示“微屿”。
- Windows 的最小化、最大化和关闭按钮位于右侧。
- macOS 按系统习惯适配窗口控制位置和拖动区域。
- 空白区域可拖动窗口，双击遵循系统最大化与还原语义。

### 5.2 全局应用栏

第二排使用三轨布局：

- 左轨：圆丘岛图标和“微屿”。
- 中轨：最长约 560px 的全局搜索框。
- 右轨：保存状态、设置和“新笔记”。

搜索框以整个窗口中心线为基准居中，不能因左右操作数量变化而偏移。窗口缩小时，搜索框允许收缩；保存状态可以先隐藏，品牌和主操作保持可见。

“检查更新”不在主窗口常驻。更新检查移入设置页；只有存在可用更新或需要重新启动时，应用栏才显示低调、明确的状态提示。

## 6. 三栏布局和折叠

主窗口保持资料库、笔记目录、正文三栏结构，并采用专业紧凑密度。

- 三栏边界可直接拖动。
- 双击边界恢复默认比例。
- 栏宽和折叠状态继续持久化。
- 正文始终拥有最高宽度优先级和最低可读宽度。

### 6.1 资料库栏

展开时显示未归档、临时收集箱、文件夹和回收站。折叠时变为功能图标竖栏：

- 保留未归档、临时收集箱、文件夹和回收站入口。
- 当前入口使用潮线和图标状态共同标识。
- 点击对应图标切换入口；独立展开按钮恢复完整资料库。

### 6.2 笔记目录栏

展开时显示当前文件夹名称、笔记数量和紧凑笔记列表。折叠时变为窄竖条：

- 竖向显示“目录 · 数量”。
- 不使用“笔记”作为折叠标签。
- 点击竖条或展开按钮恢复笔记列表。

### 6.3 窄窗口行为

窗口宽度不足时，布局依次自动收纳：

1. 先把资料库折叠为图标竖栏。
2. 再把笔记目录折叠为“目录”竖条。
3. 正文不得被压缩到低于可读最小宽度。

用户手动折叠状态与自动收纳状态必须区分，窗口恢复宽度时不得意外覆盖用户偏好。

## 7. 操作收纳

### 7.1 新建笔记

应用栏的“新笔记”打开紧凑浮层。浮层包含：

- 笔记标题输入。
- 当前目标目录。
- 创建与取消操作。

创建失败时保留标题和目录选择，并在浮层内部提供明确错误和重试。笔记目录栏不再长期展示创建表单。

### 7.2 文件夹操作

- 新建文件夹保留一个明确的 `+` 图标。
- 重命名、移动和删除收入选中项的 `···` 菜单。
- 不再常驻展示一排禁用的文字按钮。
- 危险操作必须保留现有恢复或阻止误删语义。

### 7.3 搜索

- 搜索输入后直接展示结果浮层，不需要单独的“搜索”按钮。
- 不在搜索框下方长期显示使用说明。
- 占位文本说明支持标题、正文和 `#标签`。
- 搜索错误显示在结果浮层内，不推动三栏布局。
- 键盘可以打开搜索、浏览结果、选择结果和关闭浮层。

### 7.4 编辑器工具栏

编辑器工具栏保持纤薄，包含：

- 可识别的当前标题。
- 紧凑标签入口。
- 源码、分栏和预览三种视图控制。
- 更多操作菜单。
- 保存中、已保存和保存失败状态。

所有界面图标使用统一的 SVG 图标组件，不再使用字体字符、Emoji 或不一致的符号模拟图标。

## 8. 空状态和反馈

无笔记被选中时，正文显示低对比度圆丘岛轮廓、简短说明和“新建笔记”操作。文案从用户行动出发，不使用纯情绪装饰。

反馈遵循就地原则：

- 新建错误留在创建浮层。
- 搜索错误留在搜索结果浮层。
- 保存错误留在编辑器工具栏。
- 文件夹和删除反馈出现在对应栏内。
- 窗口操作失败不得影响笔记内容和自动保存。
- 主题切换不得重置栏宽、折叠状态、当前目录或当前笔记。

加载状态使用稳定占位，不让三栏尺寸跳动。错误文案必须说明发生了什么以及用户可以采取的下一步。

## 9. 组件与架构边界

主窗口重设计沿用当前 React、TypeScript、Tauri 和普通 CSS 技术边界。

建议的表现层组件：

- `AppChrome`：自绘标题栏和窗口控制。
- `GlobalToolbar`：品牌、搜索、保存状态、设置和新建入口。
- `LibraryRail`：资料库展开栏与折叠图标栏。
- `DirectoryRail`：笔记目录展开栏与“目录”竖条。
- `CreateNotePopover`：新建笔记浮层。
- `AppIcon`：圆丘岛 SVG 与尺寸适配。
- 统一的 SVG `Icon` 组件集合。

现有 `FolderTree`、`NoteList` 和 `EditorPane` 保留业务职责，只调整布局和操作入口。不得把文件系统、SQLite 或不受限制的 Tauri 调用放进 React 组件。

自绘窗口的最小化、最大化、拖动和安全关闭通过窄 typed port 与平台适配器提供。关闭流程必须继续遵守现有的编辑器刷新和安全退出协议。

为避免继续扩大单一全局样式文件，样式可以按基础 token、窗口外壳、资料库、目录、编辑器和浮层拆分，但不引入第二套样式方案或组件框架。

## 10. 可访问性

- 所有图标按钮提供明确可访问名称和提示。
- 键盘可以到达标题栏操作、搜索、资料库、目录、正文和浮层。
- 折叠栏必须能通过键盘展开和切换。
- 焦点使用清楚的双层焦点环，不能只靠色相变化。
- 选中、保存、错误和禁用状态不能只通过颜色传达。
- 浮层正确管理焦点进入、Escape 关闭和关闭后的焦点恢复。
- 深浅主题均满足正文、次要文本、代码和控件对比度。
- 尊重 `prefers-reduced-motion`。

## 11. 必要验证范围

本轮验证遵循 `AGENTS.md` 的按风险分层原则，只运行与主窗口表现层直接相关的检查。

必要的自动验证：

- 定向组件测试：自绘标题栏、应用栏、创建浮层、搜索结果、资料库折叠、目录折叠、键盘操作和主题状态。
- 相关 TypeScript 类型检查。
- 相关 CSS 和组件 lint。
- 圆丘岛图标的小尺寸和配置合同检查。

必要的手工验证：

- Windows 主窗口浅色和深色主题。
- 资料库与目录的展开、独立折叠和同时折叠。
- 约 1024px 和较宽窗口下的搜索居中与正文宽度。
- 标题栏拖动、最大化、还原和安全关闭。

本轮默认不运行：

- Rust 全量测试。
- 10,000 笔记搜索夹具。
- 发布工作流和安装器全流程。
- 与本轮未修改模块无关的全量 E2E。

若实施过程中实际修改了 Rust 窗口边界，则只补运行相关 Rust 单元或集成测试。macOS 保留适配实现和风险记录；没有真实 macOS 主机时不得声称完成原生 GUI 验证。

## 12. 验收标准

设计完成后应满足：

1. 主窗口不再出现浏览器默认控件感、常驻开发按钮或松散的操作表单。
2. 品牌在顶部只出现一次；第一排标题栏不显示图标或名称。
3. 搜索框更长并按窗口中心线居中。
4. 正文获得最高空间优先级。
5. 资料库可折叠为功能图标竖栏，笔记列表可折叠为“目录”竖条。
6. 浅色和深色主题具有一致的现代视觉层级。
7. 新建、搜索、文件夹操作和更新入口被正确收纳。
8. 圆丘岛图标在 16px 到应用商店大尺寸之间保持可识别。
9. 现有 Markdown、数据安全、自动保存、恢复和键盘不变量不被削弱。
